# Aisth 작업 지침

## 기본 방향
- Aisth는 구버전 엑셀 중심 구조의 경직성에서 벗어나기 위한 개편 작업을 진행한다.
- 기존 `LTRYI-grammar-lesson-questions.xlsx` 참조를 전제로 새 기능을 억지로 끼워 넣지 않는다.
- 앞으로는 각 exercise가 서로 다른 문제 형식, 렌더링 방식, 채점 방식, 상호작용을 자유롭게 가질 수 있다는 전제로 설계한다.

## 데이터 설계 의도
- exercise별 데이터는 처음에는 JS/JSON 등 자유로운 구조로 작성할 수 있다.
- 다만 나중에 작성된 데이터를 다시 추려서 엑셀화하거나 한 번에 불러오기 쉽게 만드는 가능성은 열어둔다.
- 그래서 완전히 제각각인 필드명보다, 가능하면 공통 열로 옮기기 쉬운 이름을 우선 고려한다.
- 권장 공통 축은 예를 들면 `lesson`, `exercise`, `title`, `type`, `prompt`, `answer`, `choices`, `hint`, `explanation`, `metadata` 같은 식이다.
- 단, 공통 열에 맞추기 위해 exercise 고유의 학습 경험을 망가뜨리지 않는다. 필요한 경우 `metadata`나 exercise 전용 필드를 둔다.

## 구조 개편 의도
- 현재는 각 lesson JS의 `injectRuntimeStyles`, 개별 렌더 함수, 채점/결과 처리 코드가 너무 많은 책임을 떠안고 있다.
- 새 작업에서는 반복되는 UI, 스타일, 문제 로딩, 결과 처리, helper를 가능한 공용 파일로 묶는 방향을 우선한다.
- exercise 파일은 해당 exercise의 데이터, 화면 구성 의도, 특수 상호작용만 담는 쪽을 목표로 한다.
- 공용화는 한 번에 과하게 하지 말고, 실제 중복과 책임이 보이는 지점부터 점진적으로 분리한다.

## 기존 파일 취급
- 기존 한국어 텍스트와 인코딩 문제를 주의한다.
- 파일 읽기/쓰기 시 루트 `AGENTS.md`의 인코딩 규칙을 따른다.
- 기존 lesson을 뜯어고칠 때는 사용자가 설계를 설명한 뒤 진행한다. 임의로 큰 구조 변경을 먼저 하지 않는다.

## 현재 개편 메모
- 7-4, 7-5의 관계사 내용은 Aisth가 아니라 Herma에서 다루는 방향이다.
- Aisth 쪽에는 별도 예비 페이지나 새 exercise로 의문사 같은 더 앞단의 개념을 다룰 수 있다.
- `aisth-lme1`은 의문사가 무엇인지 소개하는 front-only 실험 페이지로 둔다.
- `aisth-l0e1`은 현재 frame 구조 전환과 문제풀이 UI 정리 작업 중이다.
